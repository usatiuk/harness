# Desktop v1

Status: Complete

## Outcome and accepted scope

Ship a Tauri 2 desktop client using React, TypeScript, Vite, React Router data
routes, Radix Themes controls, and restrained desktop CSS. One selected conversation is visible; every
conversation created or opened in this app remains independently active and its
status remains visible in the sidebar. Provide history/resume, streaming Markdown,
tool arguments, edit diffs and output inspection, inline approvals, send/queue/steer,
interrupt, model/preset/backend selection, and basic provider/global settings.
Closing the window quits the application and cleanly stops server-owned work.

The user approved this scope on 2026-10-03. Side-by-side conversation views, an IDE,
worktrees, tray operation, a daemon/shared GUI-TUI connection, and parallel TUI
presentation are outside v1. GUI and TUI share durable Harness data but only one
server may own a database at a time. Credentials remain in the existing server
credential store. UI drafts and appearance preferences are client-owned.

## Grounded design

- Extract the shipped composition and feature RPC registration from the CLI into
  a server package; both clients use the existing JSON-RPC service boundary.
- Give plugin contracts/presentation code browser-safe entry points. Reuse the
  transcript reducer and plugin client rather than duplicate interpretation.
- Tauri owns bundled Node, server resources, pipes, and final shutdown. Rust does
  not implement conversation semantics. Preserve existing frame/queue bounds.
- Use SQLite's native exclusive locking for server database ownership if process
  tests establish exclusion and release after normal exit and crash.
- Router loaders load bounded initial data; actions/fetchers issue mutations and
  own pending/error states. A client session above the router owns subscriptions;
  navigation never ends conversation work. Live events update presentation.
- Providers are composed at startup. Sign-in changes require an explicit clean
  server restart; retain durable history and explain interruption before restart.
- Inspect Photos's process ownership/testing patterns and Planner's route data
  patterns. Give Harness its own interface. Validate the actual Windows native app in this environment; qualify
  untested platforms rather than claiming cross-platform evidence.

Primary references informed the narrow bridge and route design:
[Tauri Node sidecars](https://v2.tauri.app/learn/sidecar-nodejs/),
[Tauri channels](https://v2.tauri.app/develop/calling-frontend/#channels),
[capabilities](https://v2.tauri.app/security/capabilities/),
[React Router actions](https://reactrouter.com/7.18.4/start/data/actions), and
[SQLite exclusive locking](https://www.sqlite.org/pragma.html#pragma_locking_mode).
SQLite owns the database lock; existing JSON-RPC owns message semantics; Tauri
owns only process/pipe lifetime. No daemon, alternate engine, or generalized
runtime abstraction was introduced.

## Evidence and remaining work

Server extraction and the native/React vertical slice are implemented. Focused
CLI/shared-presentation tests pass (64 tests), and the real server process test
establishes database exclusion and release after normal shutdown and a crash.
The browser and Rust debug/release builds pass. The Windows NSIS installer builds
with bundled Node v24.19.0 and 43 runtime/native dependencies. All ten actual native
E2E scenarios pass against the staged production release. Visual inspection confirms a restrained
desktop layout and readable edit/output inspection.

Independent reviews reproduced and drove fixes for concurrent credential-file
mutations, OAuth abort-listener cleanup, safe key-validation errors, discarded
cleanup failures, stale detached views, sidebar pagination reset, preset loss,
and unavailable-model presentation. A public-client regression prevents unseen
subagent output from filling an attachment-only backlog and disconnecting roots.
The native ownership reviewer reproduced blocked-write shutdown and false-success
exit bugs, then verified the fixes against the actual app: writes cancel promptly,
duplicate stops wait, and replacement starts only after the old child exits.
Shutdown timeout was reported at 20.036s and replacement admitted at 20.037s.

The expanded native suite establishes diff/large-item/virtualized-history
inspection, queue/steer, encrypted credential storage and restart, crash recovery,
database exclusion/retry, and failed shutdown reporting. Actual PowerShell and
Node PIDs disappear after clean quit. Public regressions cover repeated failed
reattachment and shutdown disposal failures. Final rechecks found Windows case
aliases bypassing credential coordination, child-only sidebar pages resetting
pagination, and an unobserved oversized-attachment shutdown rejection; each was
fixed at its existing owner with a regression.

The first staged release launch exposed a Windows verbatim resource path that
Node rejected. The native boundary now uses `dunce::simplified` where equivalent,
before launching Node and passing its script path. The corrected release passed
all ten native scenarios in 53.2 seconds outside the checkout with no system Node
on the application PATH. The native reviewer independently verified matching
hashes for the staged executable, server bundle, Node runtime and LICENSE, and
ran the packaged devcontainer CLI with packaged Node (`0.80.3`). No review/test
native applications remain running.

Final `npm run check` passes type checking, lint, formatting, and 829 tests
(30 platform/opt-in skips; 92 passing files). Rust formatting and Clippy with
`-D warnings` pass. Three independent read-only reviewers covered client behavior,
server/plugin boundaries, native ownership/packaging, tests/documentation, and
simplicity; confirmed findings are resolved and rechecked. Required behavior is
implemented and verified, with coherent source/documentation commits and push
authorized by the user.
